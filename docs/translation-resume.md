# 全文翻译断点保存与继续

2026-11-17 已实现并安装。

- 每批结果完整返回并校验所有句子后，把已经完成的译文、对应源文和术语表写入论文目录中的 `checkpoint.json`。
- 断点采用同目录临时文件写入再原子替换；先提交断点，再更新 `state.json` 进度，避免状态已增加但译文尚未保存。
- 网络失败、API 错误、暂停或退出中断后，`translated` 仍为 false，已提交批次保留。
- 重新加载插件时从断点恢复实际完成数量，即使状态文件中的进度较旧。
- 点击“继续全文翻译”时重新提取并分句当前论文，逐项比较源文和目标语言。匹配时从已完成句数继续，并携带恢复的术语表，不重发已完成批次。
- 原文、分句结果或目标语言不匹配时不混用旧译文；旧断点另存为 `checkpoint-previous-<timestamp>.json`，新内容从头处理。
- 如果只剩最后的文件整理或状态提交未完成，直接从完整断点生成最终文件，无需再请求服务商。
- 全文最终文件和 true 状态提交成功后清理断点；最终术语与译文保留在 `translation.json`。
- 界面显示“已保存 X/Y”和“继续全文翻译”；运行中可点击“暂停并保存”。暂停保留已完成批次，未完成的当前请求在下次继续时重试。
- 不自动重新发起论文翻译；用户点击继续后才请求服务商。

## 保存粒度与兼容边界

保存单位为一批完整、有效的结果。请求还在流式输出或返回了不完整 JSON 时，该批没有可用提交，下次重新请求该批；此前完整批次不受影响。

旧版中断任务只有进度计数、未保存批次译文，无法从计数恢复已经丢失的结果；该功能从本次更新后的请求开始保存实际译文断点。
